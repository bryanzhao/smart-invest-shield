# AI 原生投资风控系统：首期规划

## 已确认方向

- **产品目标**：先做客户可用的试点闭环，而不是只做内部研究工具或静态展示页。
- **首页入口**：国家认知地图。这里暂按“围绕一个国家的监管、政策、流程、竞品、人物和风险关系进行浏览”的认知工作台理解，不做纯地理地图。
- **组织范围**：首期支持多个国家、多个投资项目的基础结构，但用一个试点国家和一个重点项目验证完整流程。
- **核心角色**：
  - 决策层：浏览判断、证据、变化、提交 Issue。
  - 研究/交付团队：拆解问题、采集情报、分析、复核、发布和响应 Issue。

## 一、产品信息架构

```text
登录
 └─ 国家认知地图
     ├─ 国家总览：进入判断、风险温度、最新变化、待处理 Issue
     ├─ 监管与政策：政策原文、解读、影响评估、证据等级
     ├─ 关键流程：许可/外资审查/补贴等节点、材料、时间窗口
     ├─ 竞争格局：公司档案、项目动态、市场位置
     ├─ 关键人物：监管部门、竞品高管、决策网络与变动
     ├─ 风险清单：Top 10、风险变化、应对建议、负责人
     └─ Issue 中心：问题提交、研究过程、响应、历史知识沉淀

研究/交付工作台
 ├─ 项目与国家管理
 ├─ 情报采集与来源管理
 ├─ 问题拆解与研究任务
 ├─ AI 分析草稿
 ├─ 证据复核与发布审批
 └─ 月度简报 / 季度风险重启
```

## 二、首期关键界面

### 1. 国家认知地图（决策层首页）

- 顶部切换国家、项目和时间范围。
- 中心展示“市场进入判断”与当前风险温度，不把 AI 聊天框作为主入口。
- 以认知节点/关系层呈现监管、政策、流程、竞品、人物和风险；节点点击后进入有证据支撑的详情。
- 右侧或下方展示“最近变化”：政策修订、监管换届、竞品动作、风险升级/缓解。
- 每个判断都能追溯到来源、发布日期、证据等级、研究结论和最后复核时间。

### 2. 风险清单

- Top 10 风险卡片：严重度、趋势、置信度、证据等级、影响范围、应对建议。
- 支持季度重启：对比上季度，标记已缓解、已升级、新增和假设失效。
- 决策层可评论或将风险转成 Issue；研究团队可维护状态和责任人。

### 3. 政策与流程详情

- 政策原文与多语种来源、中文解读、影响评估、适用条件、生效时间。
- 关键流程用时间线展示节点、前置材料、监管部门、预计窗口和不确定性。
- 政策变化自动关联受影响的流程、项目和风险，避免信息孤立。

### 4. 竞品与人物档案

- 公司卡片：业务、项目、合作方、采购/招投标、近期动态。
- 人物卡片：职位、机构、关联事件、任免变化、公开来源。
- 关系图只呈现可解释关系，所有边均需有证据或明确标记为待验证。

### 5. Issue 中心

- 类 GitHub Issue 的问题提交：问题、项目、国家、优先级、期望交付时间。
- 研究团队内部拆解为子任务，绑定来源和结论，经过复核后发布响应。
- 记录响应版本、参与者、证据、结论和未解决事项，逐步形成可搜索知识库。

### 6. 研究/交付工作台

- 用工作流状态管理：待拆解 → 采集中 → 分析中 → 待复核 → 已发布。
- AI 只生成可编辑草稿和候选关联，不直接替代人工发布。
- 研究团队可以调整证据等级、驳回结论、补充来源并保留审计记录。

## 三、后台能力设计

### 1. 核心数据对象

- `organization`：客户组织与成员。
- `user_roles`：独立存储角色，不把权限写在用户资料中。
- `country`、`investment_project`：多国家、多项目基础结构。
- `intelligence_node`：政策、部门、流程、公司、人物、事件等认知节点。
- `relationship`：节点之间的可解释关系与来源。
- `source`：URL、原文、语言、发布时间、抓取时间、可靠性、证据等级。
- `risk`：风险、评分、趋势、假设、影响、应对建议、复核周期。
- `issue`、`issue_task`、`issue_response`：问题、研究任务和正式响应。
- `review`、`audit_log`：复核、发布和关键操作留痕。

### 2. AI 原生处理链

```text
决策问题
 → 问题分解与情报需求配置
 → 多语种公开信息采集
 → 去重、抽取、实体与关系识别
 → 多角度分析：政治/监管/经济/竞争
 → 证据绑定与冲突检测
 → 人工复核
 → 风险/认知地图/Issue 响应发布
```

AI 的边界：可以检索、归纳、关联、提出假设和生成草稿；不能无证据生成事实、跳过复核直接发布，不能替代法律意见或投资决策。

### 3. 更新与通知

- 政策、监管机构、人事、竞品和行业动态按配置频率更新。
- 变化触发受影响节点、项目和风险的关联更新。
- 对风险升级、重要政策变化、Issue 临近 SLA 发送站内通知，后续再接邮件/企业协作工具。
- 每季度生成风险重启任务和前后对比视图。

## 四、分阶段实现

### Phase 0：运行基础与可演示骨架

- 先排查并修复当前 `@tanstack/react-start` 客户端动态模块加载失败，确认根路由可稳定加载。
- 建立应用壳、角色视图、国家/项目切换和路由骨架。
- 以提案中的意大利案例作为演示内容参考，但所有内容标注为演示/待核验，避免伪装成实时数据。

### Phase 1：客户试点最小闭环

- 国家认知地图总览。
- 一个重点国家、多个项目的结构。
- 风险 Top 10、政策/流程、竞品/人物档案。
- Issue 提交、研究状态、证据绑定、人工复核、正式响应。
- 基础权限：决策层只读/提问，研究团队可编辑/复核/发布。
- 先用结构化演示数据验证界面和工作流，再接真实采集与持久化。

### Phase 2：持续跟踪与订阅价值

- 多语种 OSINT 采集任务与来源入库。
- 变化检测、影响传播、通知。
- 月度简报生成与审核。
- 季度风险评估重启及历史版本对比。
- 知识库全文检索与 Issue 历史复用。

### Phase 3：规模化与平台集成准备

- 多组织隔离、审计、数据导出和更细粒度权限。
- 研究指标、SLA、交付质量和来源覆盖度。
- 对接星瀚现有投资流程/阿凡达平台时，保留国家、项目、风险、证据和 Issue 的稳定接口。

## 五、首期验收标准

- 决策层能在 3 分钟内回答：能不能进、主要风险在哪、最近发生了什么、依据是什么。
- 研究团队能在一个 Issue 中完成：问题拆解、来源收集、结论撰写、复核、发布和留痕。
- 任一关键判断都能展开到证据、原文、时间和复核状态。
- 一个政策或人物变化能够显示其影响到的流程、项目和风险。
- 季度重启能清楚比较风险的升级、缓解、新增和失效假设。
- 多项目基础结构已存在，但试点内容不会被过度平台化拖慢。

## 六、实施前需要继续确认的产品决策

1. 首个演示国家是否采用意大利，还是以客户最终确认的目标国为准？
2. “国家认知地图”第一版采用关系图/节点图，还是采用左侧主题导航 + 右侧详情的地图式工作台？默认建议先做后者，关系图作为可展开视图，降低认知负担。
3. 研究团队是否需要客户内部风控/法务作为第三种角色参与复核？当前按已确认的两类角色设计，但数据模型预留复核者。
4. 首期是否需要真实外部信息采集，还是先用可核验的样例来源完成客户演示后再接采集管道？默认建议先做“真实来源 + 半自动入库”，避免演示内容失去可信度。

## 技术实现说明

- 继续使用现有 TanStack Start + TanStack Router + React Query + Tailwind 设计系统，不引入另一套路由或页面架构。
- 需要持久化、登录和权限时启用 Lovable Cloud；敏感数据按组织与用户权限隔离，角色放在独立角色表中。
- 后端采用类型安全的 server functions；外部回调、公开接口和采集 webhook 使用 server routes。
- 每个内容路由提供独立页面元数据；不把主要模块全部堆在首页或仅用 hash 锚点实现。
- 所有视觉颜色、边框、阴影使用全局语义 token；界面方向建议采用克制的深色投资研究工作台，而不是营销型渐变页面。
